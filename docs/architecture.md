# 架构说明

## 定位

本项目是「地图是导航的度量底座」这一理念的代码载体。它不替代 SLAM、图优化器、地图服务或渲染引擎，而是定义它们之间的**坐标契约与状态契约**。

## 分层

```text
┌─────────────────────────────────────────────────┐
│ 未来：高德 API / 高斯泼溅 / 元宇宙              │
├─────────────────────────────────────────────────┤
│ 状态运行时 fork_spatial_runtime                 │
│   状态生命周期 / 原子事务 / 版本化快照          │
├─────────────────────────────────────────────────┤
│ 哈希瓦片底座 spatial_map                        │
│   地理锚定 → WGS84 → GCJ-02 → z/x/y → 哈希存储  │
├─────────────────────────────────────────────────┤
│ LIO 前端（如 Super-LIO）：局部 ENU 增量位姿     │
└─────────────────────────────────────────────────┘
```

## 关键设计决策

1. **LIO 局部坐标经地理锚定接入全局**：Super-LIO 等前端输出局部 ENU 位姿；通过地图原点经纬度 + 航向换算为 WGS84。这层锚定正是"map → odom 吸收全局定位修正"的代码化。
2. **瓦片 ID 对齐主流地图服务**：采用 Slippy Map / XYZ 的 `z/x/y`，与高德、OSM 一致；局部 SLAM 状态嵌入后即可与城市级底图对齐。
3. **GCJ-02 对齐高德底图**：高德底图使用 GCJ-02 加密坐标，与 WGS84 有约百米偏移；先 `wgs84_to_gcj02` 再取瓦片，才与高德底图逐像素对齐。境外不偏移，往返误差 < 0.01m。
4. **固定容量开放寻址哈希**：延续 MISRA 精神的有界资源与无动态分配；查询 O(1) 均摊，重复瓦片幂等拒绝。
5. **瓦片作为 `SubmapPose` 状态**：状态值存瓦片西北角经纬度 + `z/x/y`，生命周期与版本由运行时统一管理。
6. **重复不重提、无效不推进版本**：瓦片层与状态层各自幂等，重复提交不改变 `graph_version`。

## 路线图

| 1 | 哈希瓦片编码 + 状态事务组合 | 已实现 |

## 边界

- 不是完整 SLAM：不含前端、图优化器后端。
- 不是地图服务：不含瓦片渲染与数据分发。
- 是两者之间的**契约层**：定义坐标如何哈希、状态如何版本化、快照如何查询。
